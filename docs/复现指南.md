## 一、这个项目解决什么问题

手机拍的学生试卷（满页红蓝手写）直接喂 OCR，**手写会被当成题目内容**，识别结果一团糟。
这个项目给出的路子是：

**先把手写擦掉、拿到干净版面 → MinerU 转录 → 逐题对照原图校对润色 → 把题解出来 → 出学生版 / 教师版 PDF。**

它不只是"一个能跑的脚本"，而是一条在**真实高三试卷上反复实测**打磨出来的流程，含两条核心经验：

1. **去手写版是更好的转录源，但手写压印过的印刷字会被擦糊** —— 那几处必须回原图 + 用数学反推双验。
   实证：某题椭圆方程被手写完全盖死，靠"若 $\frac{x^2}{4}+\frac{y^2}{3}=1$ 则与 $y^2=4x$ 交于 $x=\frac23$，
   得 $|AB|=\frac{4}{3}\sqrt6$ 正合选项 B"一击锁定，比对着糊图猜可靠得多。
2. **去手写会把学生填进"印刷空格 / 横线作答处"的答案一并擦掉** ——
   凡印刷体留空、横线、`______` 的位置，**必须回原图看学生填了什么**。

流程封装为技能 **`handwritten-paper-transcribe`**，九步：

```
0 拿图 → 1 去手写 → 2 合 PDF → 3 MinerU 转录 → 4 图形核对
→ 5 逐题对照原图校对润色 → 6 落盘自检 → 7 解题与数值自验 → 8 出片（学生版/教师版） → 9 交付
```

## 三、环境准备

| 依赖 | 参考路径 / 版本 | 怎么装 |
|---|---|---|
| 扫描全能王 CLI（去手写） | `~/.local/bin/camscanner-cli` v1.1.8　**不在 PATH** | 装 `camscanner` 技能 → 跑它的 `scripts/setup.sh`；再 `auth login` 前台登录 |
| MinerU CLI（转录） | `~/.local/bin/mineru-open-api` v0.5.9　**不在 PATH** | 装 MinerU CLI，token 写到 `~/.mineru/config.yaml`（权限 600） |
| Python（Pillow / numpy） | 托管环境 python | 需带 Pillow、numpy |
| Python（PyMuPDF `fitz`） | `/opt/homebrew/bin/python3` | 出片链需要 fitz |
| 出片脚本 | `~/.workbuddy/skills/math-handout-pdf/scripts/build-handout.py` | 随 `math-handout-pdf` 技能 |

> 两个 CLI 都**不在 PATH**，命令行里请写绝对路径。

## 四、复现步骤

设工作目录 `$W`，卷名简写 `$V`。**本仓库不含原始照片，第 0～2 步请用你自己的试卷照片**；
若只想验证方法，可直接从第 3 步起步：拿 `examples/案例A-向明中学10月学科检测/1-MinerU原始输出/` 作为起点，对照 `2-交付物/` 的成品。

```bash
CLI=~/.local/bin/camscanner-cli
MINE=~/.local/bin/mineru-open-api
PY=~/.workbuddy/binaries/python/envs/default/bin/python
SKILL=./skills/handwritten-paper-transcribe        # 或拷到 ~/.workbuddy/skills/ 后引用
```

**第 0 步 · 拿到能读的图**
照片放到可读目录（macOS 剪贴板目录 `~/.workbuddy/clipboard-images/` 可读；微信 `~/Library/Containers/...` 读不了）。
校验：JPG/JPEG/PNG、单张 ≤ 40 MB。

**第 1 步 · 去手写（逐张，别并发）**

```bash
mkdir -p "$W/$V 去手写"
"$CLI" image enhance "<原图>" --mode 9 -o "$W/$V 去手写/$V 第N页 去手写.jpg"
sleep 2
```

只给 `-o`、**不要加 `-s`**（`-s` 会把结果写进你的扫描全能王云端账号）；`-o` 会静默覆盖，写前先判存在。
**注意**：该服务为云端处理，输入图片会上传；**含学生姓名 / 学号的卷子请先裁掉或打码**。

**第 2 步 · 合 PDF（页序显式传入，别用 glob）**

```bash
"$PY" "$SKILL/scripts/images_to_pdf.py" "$W/$V 去手写版.pdf" "<第1页>" "<第2页>" "<第3页>" --dpi 200
```

**第 3 步 · MinerU 转录**

```bash
"$MINE" extract "$W/$V 去手写版.pdf" -f md -o "$W/mineru_out/" --model vlm --language ch
```

**第 4 步 · 图形完整性核对**
`images/` 里的图要与正文引用一一对应。引用有、磁盘没有 → 回 PDF 补裁；磁盘有、正文没引用 → 多半是公式碎片。

**第 5 步 · 逐题对照原图校对与润色（最花时间，别跳）**
双源交叉：**去手写版读正文，原图读被压印处的残影与印刷留空处的学生答案**。
窄区放大用两步定位法，别盲试框：

```bash
"$PY" "$SKILL/scripts/crop_zoom.py" "<原图>" "$W/crops/qN_定位.jpg" --grid
"$PY" "$SKILL/scripts/crop_zoom.py" "<原图>" "$W/crops/qN_放大.jpg" --box 0.30,0.735,0.50,0.768 --scale 6
```

MinerU 高频错型对着 `$SKILL/references/mineru-math-error-catalog.md` 逐题过。
润色只做两件事：**修正识别错误** + **规范标点与题号样式**；题干逐字保留，不改写、不补写。

**第 6 步 · 落盘与自检**

```bash
"$PY" "$SKILL/scripts/check_transcribe.py" "$W/$V 转录稿.md"     # exit 0 才算过
```

**第 7 步 · 解题与数值自验**
把全部题解出来；原卷只给答案没给过程的**不补写解析**；难题写脚本独立复算
（参考 `examples/案例A-向明中学10月学科检测/3-解题与数值自验/`）。条件不确定的题标"待核"，不猜值。

**第 8 步 · 出片**

```bash
"$PY" "$SKILL/scripts/make_student_md.py" --src "$W/$V 转录稿.md" --out "$W/$V 学生版.md" \
  --heights "17=80,18=80,19=120,20=120,21=150"
python3 ~/.workbuddy/skills/math-handout-pdf/scripts/build-handout.py \
  --src "$W/$V 学生版.md" --out "$W/$V 学生版.pdf" \
  --mode student --theme color --build "$W/build-student" \
  --expect-boxes 21 --box-mm 40,40,40,40,40,40,40,40,40,40,40,40,40,40,40,40,80,80,120,120,150
```

教师版：先按 `**答案**` / `**解析**` 的标签行结构补全（答案紧跟试题），再 `--mode teacher --theme color`。
**自检要全绿才算交付。** 出片参数以 `math-handout-pdf` 技能为真源；详见
`$SKILL/references/handout-build-and-delivery.md`。

**第 9 步 · 交付**
产物与 md、`images/` 同放一个专属目录，文件名中文、不用下划线。

## 五、怎么验证你复现对了

| 验证点 | 案例A 向明中学 | 案例B 综合练习（一） |
|---|---|---|
| `check_transcribe.py` | **PASS / exit 0**：374 个 `$`（成对）、0 个 `$$`、5 处图引用、0 孤儿 | **PASS / exit 0**：330 个 `$`、0 个 `$$`、3 处图引用、0 孤儿 |
| `make_student_md.py` | 题号 21 == 作答框 21、图 5、泄漏词命中 **0** | 题号 21 == 作答框 21、图 3、泄漏词命中 **0** |
| 学生版 PDF | A4 **10 页** | A4 **9 页** |
| 教师版 PDF | A4 **10 页**（出片自检 11/11 全绿） | 本案例未出教师版 |
| 交付文件哈希 | 见 仓库内各文件的 git 历史 | 同左 |

`--expect-boxes` 必须等于 md 里 `class="answer-space"` 的实际个数，先 `grep -c` 再填。

> **两个口径提醒（都是实测踩出来的）**
> 1. `check_transcribe.py` 自 v1.2.0 起会跳过**行内反引号**内的内容再计数。用 v1.1.0 旧脚本跑案例A
>    会得到 `394 个 $ / 2 个 $$` —— 那 2 个 `$$` 其实是校对说明里引用的原文，不是真题块。
> 2. `--color-text-min` 需放宽：纯客观题学生版彩色字只有二三百字，传 250 左右；教师版更少时传 400
>    （实测 501 字时默认阈值会 FAIL）。

## 六、两个案例的差别（别当成不一致）

- **案例A（向明中学 10 月学科检测）**：**全链路**，含教师版、含解题与数值自验脚本。推荐先看这条。
- **案例B（高三数学综合练习（一））**：链路相同，但当时**只出到学生版**；且这份**转录稿的 frontmatter
  曾被外部改动**（写成转义形式 `\---`，`title` 与正文 H1 不一致），本仓库**原样保留**——
  它正好是"转录稿被别的工具动过"的真实样本，也是学生版脚本要兼容 `\---` 的原因。

## 七、已知限制与待核
